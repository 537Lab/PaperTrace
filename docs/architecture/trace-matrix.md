The single definition of requirements is [`docs/req/requirements.yaml`](../req/requirements.yaml); this table only traces and does not change the thresholds. **“Test defined” is not “test passed”; “the contract can express it” is not “it has run at runtime”.** A–E all await member development; every runtime monitor likewise awaits development.

## 1. Status notation

- **C (contract)**: a corresponding static contract test is already defined in the existing `test/offline/test_contracts.py`; this architecture subtask did not run it, and the real result follows the execution receipt kept by the controller.
- **G (governance)**: the existing `test/offline/test_gates.py` contains some local fault-injection tests; this must not be extrapolated to remote permissions/branch protection or to all course gates having passed.
- **P (planned)**: test intent and identifiers are designed, and the business or integration cases await development, with **no test results**. All T-A/B/C/D/E, T-INV and T-COST/SEC/PERF numbers here are planned IDs, not fabricated existing pytest nodes.
- Runtime monitoring is the observation contract after go-live; for governance requirements, runtime means CI/tool sessions/PR events, and is not forced into product model logs.

## 4. Evidence that cannot substitute for each other

1. Pydantic rejecting `actor_kind="model"` does not prove that a `human` record really came from a human; C's interaction/ledger tests are still required.
2. The subset validation of `AnswerDraft` cannot prove that approved came from the current ledger, nor that sent is really in the HTTP payload; the D/B integration test must observe the real boundary.
3. A frozen object is not the same as disk history not being overwritten; manifest/byte hash and fault injection are still required.
4. A fake model can prove deterministic guards but not scientific quality; the upstream's existing citation/summary capability does not automatically become a new team contribution.
5. Local schema/lint/log tests passing is not the same as full regression, real semantic evaluation or GitHub protection being enabled. The six gate categories report their real status separately; if one is missing, the whole cannot be called complete.

When a requirement changes, update the registry first, then sync this matrix/ADR/invariants/permissions/state/policy and tests; rules must follow human-reviewed requirement updates within one sprint. Test output must keep the real commit/version and execution scope; the P numbers here must not be changed to PASS in place of development.
