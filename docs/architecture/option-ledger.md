# Option ledger: what is rejected, and when to reconsider

> All entries are trade-offs of this architecture proposal, not decisions the student has already approved. Page 5 of the course project lists the option ledger as optional and the tree on page 9 lists it again; this round provides substantive content for traceability, but does not use it to change the grading basis unilaterally. [1]

| Option ID | Option / current handling | Reason for rejection or deferral | Explicit reopening conditions / evidence required |
|---|---|---|---|
| OPT-01 | Generate and publish directly with the as-is CLI/high-level Agent: not adopted | Automatic evidence backfill/tool loop, upfront index building, fallback outside the timeout and the human-review-first order are inconsistent (`docs.py:602–624`, `agents/main.py:121–183`) [3][8] | Only after proving that all tools/factory/SDK/HTTP are controlled and that the empty-set zero-call, three-set and freshness properties still hold; new ADR + negative tests + human approval |
| OPT-02 | Modify/replace the `src/paperqa` core: forbidden this term | Retaining a traceable baseline avoids rewriting existing upstream capability as a team innovation | When the thin adapter cannot satisfy an explicit Must, provide minimal failure evidence and an alternative comparison, and discuss reopening the frozen scope only after the student explicitly does so |
| OPT-03 | Physically deleting vectors at runtime/strong multi-store transactions: excluded from the MVP | tombstones and retrieval filtering already exist; physical deletion and recovery are additional cross-engine problems; the thin snapshot gate must not be used to quietly include the whole thing (`docs.py:403–490`) [3] | The user explicitly needs secure erasure/storage reclamation or a large corpus; specify the backend, fault model, separate budget/schedule and real-run evidence |
| OPT-04 | Third-party pickle index import/automatic migration: forbidden | There are two loaders, document and mapping; unpickling before checking is already too late (`agents/search.py:86–93,242–257`) [7] | First design a non-executable data format and schema/size/path/provenance contracts; do not offer legacy executable migration by default; separate ADR and security review |
| OPT-05 | Qdrant/database server/cloud storage: deferred | Single-machine single-user single-writer has no service requirement this term; it would introduce deployment/network/consistency costs | A measured resource bottleneck on a single machine or an explicit multi-person requirement; measure for real first, then compare local files/SQLite/service options, and do not move to the cloud on imagination |
| OPT-06 | Large web front end/public deployment/login system: deferred | The five-function task must not turn into UI/operations; the public-network/multi-user permission model differs from the current threat boundary | Real target users and concurrency requirements approved, core invariants/tests complete; new deployment/auth/data/privacy design |
| OPT-07 | Automatic metadata/citation inference/media enrichment/pre-post: off by default | Extra outbound calls, cost and raw citation changes enlarge the controlled surface; only None really turns pre/post off (`docs.py:180–311,626–639,694–711`) [3] | Explicit product requirement, per-path metering coverage and license/data approval; any final processing must still pass the D release gate again |
| OPT-08 | Automatically accepting model summaries and treating score as confidence: rejected | The model has no review authority; relevance is not scientific truth or a human review record | Cannot be reopened under the current INV-03; if the product is to change the authority boundary, the requirements/invariants must be changed openly with student and course permission, rather than handing over authority quietly via a prompt |
| OPT-09 | LLM context compression/Reflexion autonomous retry: not done in the MVP | It can consume more calls, pollute identity/decisions and hide repeated generation; the fixed pipeline is sufficient | Deterministic trimming proven insufficient by data; approve model/amount/data/count separately; compression fidelity/constraint reinjection and termination negative tests complete |
| OPT-10 | Automatically proving all scientific claims/finding every contradiction: not promised | A locatable citation/quote is not semantic entailment or factual correctness | An explicitly bounded human rubric/evaluation or auxiliary conflict hints may be added, but must not be upgraded into a zero-tolerance code-based truth certification |
| OPT-11 | Automatically migrating the accepted status of an old snapshot to a new snapshot: not adopted | A new snapshot has a new evidence identity; the same abstract/same body text does not mean current review authorization | First define a verifiable migration proposal, explicit user confirmation item by item and new ledger events; bulk copying must not be treated as the original decision still being valid |
| OPT-12 | Maintaining two complete blueprints separately: rejected | The course layout has two entries, and two bodies drift easily | Only if the teacher explicitly requires two complete copies, consider generating them from a single source with a consistency gate; by default the root is canonical + a pointing page |

Reopening is not “already permitted”: submit trigger evidence → compare a smaller alternative → impact on ADR/requirements/contracts/tests/trace/permissions → the student approves in person → OpenCode plans first and then stops for human review. Old entries are kept and new conclusions appended; the original reason for rejection is not deleted to disguise scope expansion.
