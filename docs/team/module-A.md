# 模块 A｜文献库、导入状态与文献版本

> 可独立认领：成员 A。长期功能 ownership 不随流程轮换改变。本轮初始化未实现本模块；拿到任务书后先做审核与 OpenCode Plan，不能直接开始无人监督 Build。

## 1. 目标用户与完整用户流程

研究者明确选择自己有权使用的本地 PDF/TXT → 看见每个文件的等待/处理中/成功/失败及原因 → 得到只包含可用版本的文献库快照 → 换版或移除文献时创建新快照 → 仍能查看历史研究使用的原版本。

你负责的不只是上传表单，而是**文库身份、状态、版本、快照与自己的 library view**。首个轻量 UI 装配 PR 也由 A 发起，但这只是额外集成工作，不替代本模块功能；其他成员各做自己的 view。

## 2. Must 需求与明确不做

| ID | 必须实现的行为 | 可检查的验收语义 |
|---|---|---|
| `FR-A-01` | 明确导入本地 PDF/TXT，逐文件状态/失败原因；logical ID 与内容 SHA256 分离 | 已批准导入用例全部通过；失败项不消失、不伪装 ready；同名换内容不沿用旧内容版本 |
| `FR-A-02` | 新版本/移除创建不可变 snapshot；旧版本及历史不被覆盖 | 历史 snapshot 被改写数量为零；旧记录仍可解析到原版本，当前指针可变但旧值不可变 |
| `INV-02` | 身份、版本、定位链可核验 | 快照/文献 hash 不符时拒绝下游使用，不以文件名或上游 MD5 代 SHA256 |
| `INV-05`（与 E 协作） | 版本改变不修改旧研究记录 | 换版后旧报告内容/来源不变，只追加或投影“已被替代”提示 |
| 共同约束 | `QA-01`、`PERF-01`、`COST-01`、`SEC-01`、`GOV-01`–`GOV-04`、`INV-06/08` | 使用真实 registry 的 fit criterion；默认零模型请求、无凭据/个人信息、先批准测试和计划 |

`PERF-01` 是小型契约往返性能，不是论文解析或 PaperQA2 提速承诺。所有阈值、优先级以 `docs/req/requirements.yaml` 为准；本任务书不降低零容忍不变量。

**不做：**全网抓论文、云端/多用户库、收费 OCR、多模态、物理向量删除、自动 dedup 论文语义、判定论文真伪、接受第三方预建索引。不得直接 import `paperqa`；解析/表示准备经 B 的中立摄取端口。上游缓存 ERROR/同名跳过问题不能靠修改冻结核心随手修补。

## 3. 输入、输出、异常与交接

| 边界 | 输入 | 输出/责任 | 异常处理 |
|---|---|---|---|
| 用户 → A | 明确允许的本地文件、人工标题/引用等元数据 | 受控托管副本、logical ID、源文件 SHA256、逐项导入记录 | 不存在/空文件/类型不符/目录逃逸/权限不足：明确失败，不扫描其他目录补文件 |
| A → B 摄取端口 | 固定版本受控文件、显式解析配置、元数据；真实调用另需许可 | B 回解析/表示成功或失败；A 持有导入状态与当前文库事实 | 超时/解析失败：记录阶段与原因，不将失败项标 ready；显式、有界重试须获批 |
| A → B/C/D/E | `CorpusSnapshot`、按版本核验/读取受控原件的端口 | 只交冻结标准模型和受限访问，不交可变 Docs | 内容版本不符或原件丢失：拒绝本轮使用，保持旧历史只读，不替成同名新文件 |

**真实合同细节：**`src/papertrace/contracts.py` 的 `CorpusSnapshot.documents` 是 `DocumentVersion` 元组，只能放 `status="ready"`；失败/处理中状态放 A 的导入记录，不塞进 frozen snapshot。`source_name` 必须是纯文件名，不含绝对路径。`snapshot_id` 由规范 ready 清单产生，与抓取时间分开；构造/解析使用共享模型，不复制私有 hash 实现。

部分失败批次在 A 的导入记录明确标为不完整；只有用户明确选择已成功子集并生成新的可核验 snapshot，才可按批准策略继续。不能一边丢弃失败项，一边显示“所有文献已完成”。

同字节重复导入默认按计划定义的幂等策略复用已有版本并提示重复；同逻辑文献换内容生成新 `version_sha256` 与新 snapshot。新标题/来源元数据对 snapshot 身份的影响以真实合同计算为准，不假定“字节相同就 snapshot 一定相同”。移除只影响新清单，历史追溯仍保留原版本；不宣称底层向量已物理擦除。

与 C/D 约定当前 snapshot token 的一致读取；与 E 约定旧版本引用及缺失状态。快照指针变更要能让在途回答失效。应用编排通过获批端口/单写者协调，不允许 D 直接读写 A 的内部文件。

## 4. 可改路径与禁止范围

默认后续写范围：

- `src/papertrace/library/`：状态/版本服务、受限存储、自己的 view；由获批 Build 创建。
- `test/offline/test_library.py`：本模块正负测试；`test/fixtures/library/`：拟议合成材料目录。
- `docs/team/module-A.md`：经审查的本任务书修订；模块设计/运行证据按批准目录存放。

以上是候选边界，不是自动写授权；Plan 须把源码、`view.py`、测试及每份 fixture 展开为精确相对文件，由人工确认当轮权限。共享样例使用 `test/fixtures/contracts/` wrapper 的 `data`，synthetic 元信息不能塞入封闭模型。

共享变更要单独申请：`contracts.py`、共享 fixtures、requirements/architecture/trace、AI-use/review/bug/debt 日志、依赖/锁、CI、顶层 UI 与应用编排。**首个装配 PR 只装配导航/端口**，入口路径须列在批准计划中，不能让其他四人都去同一 app 文件加业务。

冻结：`src/paperqa/`、`packages/`、上游 `tests/`、`pyproject.toml`、`uv.lock`。禁止访问私人目录、真实 `.pqa`/`.env`、keys，禁止擅自联网/推送/创建公开仓库。`AGENTS.md` 和权限文件是约束，不可用放宽全局权限解决阻碍。

## 5. 依赖与不等待上游的开发办法

依赖共享 models、B 的中立摄取结果及应用编排合同。B 尚未开发时，用 fake 摄取端口分别返回成功/解析失败/超时；输入是自己写的短 TXT 和最小 synthetic PDF，而不是个人论文或上游论文再分发。

至少准备：同名不同字节两版、同字节重复、一个损坏/空文件、一个不允许路径、一个批次中成功与失败并存、一个读回时内容不符、一个历史旧版本。fixture hash 用程序从实际字节计算。共享例子只引用其规范版本，不能为自己实现改共享预期。

默认 `.venv`/`requirements-init.lock` 是初始化工具环境，不保证 PaperQA2/Streamlit 业务依赖已安装；新增依赖先在 Plan 说明必要性与许可，再按授权安装。fixture 不触发模型；真实摄取可能含 embedding/元数据请求，不能因为导入本地文件就称离线。

## 6. 测试：正例、负例、回归与行为

下面是**待实现的用例语义**，不是已通过结果；在测试 docstring/参数中标真实 ID。

| 场景 | 断言（不只判断非空） | 关联 |
|---|---|---|
| 正常导入 | 每项状态与计数准确；snapshot 只含 ready；JSON 往返同一模型；原文件未修改 | FR-A-01、QA-01 |
| 同字节重导/同名换版 | 幂等策略明确；换字节的 SHA256/snapshot 更新；旧 snapshot 内容不变 | FR-A-01/02、INV-02 |
| 部分失败/超时 | 失败项与原因保留；没有失败项混成 ready；不自动重试到未批准次数 | FR-A-01、COST-01 |
| 篡改/删除/越界路径 | hash 不符或来源不可读即拒绝；无对外目录写入，无同名文件替代 | INV-02、SEC-01 |
| 历史回归 | 旧 snapshot 被 B/E 用原版本读回，换版不覆盖历史；移除不误称物理删除 | FR-A-02、INV-05 |
| 在途生成时换库 | D 捕获旧 token，切新 snapshot 后旧草稿不能发布；A 不擅自替 D 判定 | INV-04，与 D/E 集成 |
| view/服务双入口 | 显示失败与版本，不泄露绝对路径；绕过 view 仍不能越界写和伪造 ready | INV-06、SEC-01 |

行为评估重点是用户可区分“完全成功/部分失败/历史版本”，不是 AI 科学答案质量。上游真实解析集成另外记录依赖/后端与结果；未运行不填 PASS。每轮运行完整团队 prior suite，不能只跑 library。

## 7. 可审核执行计划与验收步骤

1. **Plan-1 需求审核：**读已有 `AGENTS.md`、`Prompt.md`、蓝图/ADR/registry/合同；列导入状态机、ready 快照界线、版本/重复/缺失策略和可写路径。产物必须能让非作者判断什么会失败，停下等批准。
2. **Plan-2 事前测试：**提交上表测试输入/预期及 B fake 端口；明确共享接口与第一装配 PR 的范围。测试和执行计划经非作者批准，确认本轮 Build 权限才开始。
3. **Build-1 最小纵切：**OpenCode 生成托管/状态/版本与库 view，先用合成文件；检查外部原件未改。每一步失败先留日志再修，不删除负例。
4. **Build-2 版本与历史：**加入换版/移除/不完整批次、snapshot token 与读回；和 E/D 的 fake 端口演练旧结果失效。无需等 B 真实模型。
5. **Verify：**运行 `.venv/bin/python -m pytest -c papertrace.pytest.ini test/offline` 与 [../ci/gates.md](../ci/gates.md) 的实际 gates，保留命令/返回码/版本；无模型和凭据进入离线进程。
6. **独立 PR：**演示“成功导入→一项失败→同名换版→仍查旧报告”；提供 D1–D9 证据、独立 verdict 与未完成项。只有装配需要时再发小型共享 PR，不能混改其他模块。

模块验收完成必须同时具备 Must 行为、自己的 view、可复现正负/回归、批准早于实现、真实 OpenCode session、独立审查；文档/空壳不算完成。
