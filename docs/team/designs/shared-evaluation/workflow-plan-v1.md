# GOV-02/COST-01: manual evaluation workflow preflight and independent rating intake

Tests-only proposal. Related #51/#53/#54/#44. Keep frozen cases, existing thresholds, all approved tests and product module ownership unchanged. Do not dispatch from this proposal.

## Execution design
- Use .github/workflows/semantic-evaluation.yml, only workflow_dispatch, explicit inputs target_pr, target_head (40 hex), authorization_review_id. GitHub run metadata must match selected exact PR HEAD, repository, event, workflow blob and trusted base evaluator/workflow blobs. No dispatch on push, PR, schedule or fork. The actual workflow file must first be independently adopted in trusted base; check both base and head, not just input assertions. No branch moving during run. Gate 1 correction #54 and #53 protected transport implementation must precede adoption. 
- Three jobs preflight -> collect -> finalize. Read-only GitHub scopes. Checkout exact SHA with persist-credentials:false. Use pinned Actions, no untrusted input interpolated into shell scripts, no executable arbitrary input, no secret or API key passed via workflow inputs, output or artifact. Preflight has NO provider credentials. Implement preflight(ctx, client, *, pr_number, run_id, authorization_review_id) returning head_sha, authorization and dataset_sha256 after independently reading actual GitHub metadata, using trusted base checks and existing authorization validator; reject via ValueError on invalid/missing authorization (never include credentials in error). Require current in-progress workflow_dispatch, exact current PR/base/head, actual nonparticipant reviewer with write+ permission, matching provider/model/version/data scope/fixed dataset and budget. Validate runtime and source/prompt bindings before provider invocation. Reviewer may create pending review to get native review ID then submit actual APPROVE with complete authorization; pending state itself never authorizes.
- Collect uses a separately protected environment papertrace-evaluation-execution and rechecks exact SHA, review and actual runtime immediately before passing credentials to the real B/D product transport. A public repo or unprotected shared secret is not an acceptable personal-school-key route. Environment protection and authorized project credential must be verified before any dispatch; otherwise fail closed. No use of personal key by teammates. 18 attempts max, no automatic retries or fallback, explicit cost/currency and provider-specific conservative ceiling, per-attempt timeout; stop before calling when authorization, version, cost or quota uncertain. Use captured actual B/D request, not prepare_requests output as observed traffic. Observe four real deterministic product cases; no copying oracles. Upload immutable raw capture separately as papertrace-semantic-raw with raw bytes digest. Preserve partial failure evidence; no false completed artifact.
- Finalize depends on collect and separate protected environment papertrace-independent-rating. E independently inspects raw capture and C cross-checks. E posts an actual current-head COMMENTED review with exactly one line Semantic ratings: {run_id, head_sha, raw_sha256, ratings}; rating array covers all 18 actual runs and reviewer identity matches the server author. No ratings in untrusted workflow_dispatch inputs. accept_ratings(ctx, client, *, pr_number, run_id, raw_sha256, captured_at) returns review_id, reviewer, ratings only after checking GitHub review identity, current head, permission, nonparticipation, time, exact raw digest, unique coverage and individual rating schema. No duplicate accepted intake or silently overwritten ratings. Use the same run after human environment approval; keep E/C separate notes. Re-fetch raw artifact via trusted run/ID/digest, recompute score and all original invariants; produce final report only with real evidence and matching human ratings. Official upload-artifact publishes papertrace-semantic with one report file. A separate post-run current-head independent APPROVE binds actual final report SHA. No model call in finalize.
- This proposal tests the deterministic preflight and intake contracts and structural workflow controls. Live provider adapter, bounded cost/retry, secret/environment protection, exact raw output and genuine workflow execution still require reviewed implementation and positive/negative runtime evidence. No separate provider mock may count as real quality evidence. If actual API policy/entitlement is unconfirmed, report BLOCKED instead of dispatch.
