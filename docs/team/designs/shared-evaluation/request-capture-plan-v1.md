# Evaluator request capture test proposal

The evaluator will assemble attempt evidence from the original `system` and `user` messages delivered by B's checked `request_observer` before `call_single`. The existing request planner supplies expected material for comparison. Each recorded request must come from the observer, and the evaluation collector must preserve message content, including whitespace. This supports INV-01 and GOV-02. Each attempt uses the approved fixed dataset and the versioned system prompt, and each disclosure uses GOV-03.

The tests propose `collect_attempt` as a small seam. It takes the dataset SHA-256, case, repeat, versioned system prompt, a registry of fixed-to-runtime IDs keyed by `(dataset_sha256, case_id)`, and a `drive` callable. The drive receives `request_observer` and returns D's outcome and the raw response envelope. The result includes the captured report row or `None`, the presence of D accounting, and the attempt count read from `outcome.accounting`. Successful rows use the fixed case input hash and preserve the actual request and response hashes. Invalid bindings raise before the driver is invoked, and invalid capture raises before B invokes the model. With an abstention or invalid citation, the collector retains observable accounting and leaves the report row absent. Both `None` and zero remain explicit in diagnostics.

The test suite covers QUAL-02 forward, reverse and cropped order, exact message and response hashes, canonical D citations mapped back to fixed IDs, three malformed capture shapes, three invalid bindings, citations outside the dispatched set, absent capture, D rejection accounting, and isolation between repeats. Three fixture checks call the existing request verifier on the current base. The contract cases are expected to fail at the missing `collect_attempt` entry point on the existing evaluator. The driver double makes the capture and model order observable. B's existing boundary suite separately exercises B's actual request path and zero-call cases.
