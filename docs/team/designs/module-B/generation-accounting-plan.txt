B→D 生成调用账目测试提案（待确认）

范围
本切片独立于 PR #23。PR #23 继续审查越界 sent。B 负责在受控生成桥观测回答模型的调用，D 消费生成结果。拟涉及 src/papertrace/retrieval/service.py、test/offline/test_retrieval.py 和 test/fixtures/retrieval/fake_adapter.py，沿用计划与独立测试审批流程。

现有依据
GenerationPolicy 包含配置的 provider/model。发送前 count_tokens 用于最终 prompt 预算检查。Gateway.generate 返回生成状态、实际发送的证据及引用诊断，现有结构没有调用账目。计数的位置应选在回答模型调用边界。创建 session、执行 count_tokens 或进入 docs.aquery 均不足以证明发生了模型调用。

拟议最小字段
- provider、model 取受控请求的配置，并保持其配置语义。
- answer_model_attempts 记录 B 在回答模型边界观测到的尝试数。一次尝试进入后即计入，包括调用失败。供应商内部重试可能超出 B 的观测范围。
- 若 D 需要预算诊断，可另暴露计数器返回的估算输入 token 数。
- request_id、实际 token usage、费用等字段取上游可验证元数据。有字段需求时先定义来源、可空性及失败时可见性。首轮测试优先覆盖调用尝试与来源明确的字段。

离线测试矩阵
1. 预算拒绝、空证据或裁剪后空 sent，回答模型尝试数为零。
2. 会话已建、预算已计数，回答模型从未被触达，尝试数仍为零。
3. fake 上游进入回答模型一次并返回结果，尝试数为一，provider/model 与受控配置一致。
4. 回答模型已进入后失败，尝试数保留。B 测试要求异常路径可读取账目，同时保留原异常作为 cause。
5. 返回的结果缺少计费元数据时，D 不推断实际用量或费用。若未来引入对应字段，单独测试元数据缺失与显式零值。

验证与停止条件
用合成文本和 fake 上游，零真实模型调用。D 已确认首轮所需字段。B 按下述异常契约准备测试计划；学生批准计划后准备测试，具体测试版本获独立批准后进入 B 源码实现。

D 已确认的首轮范围
首轮仅返回配置的 provider/model 与回答模型调用边界的尝试次数。进入边界即计一次，包括随后抛出异常的情况。异常路径也要让 D 读取已观测次数。确定未进入时为 0，无法观测时为 None（未知）。request ID、实际 token 用量与费用延后。
拟将调用账目作为 B 的结构化结果数据。对已有异常传播路径，拟通过携带账目的 B 异常保留原异常作为 cause。D 的接线可在 B 契约确定后并行处理。测试应覆盖 0、1、异常保留 1、未知，以及调用计数不混入 token 估算。
