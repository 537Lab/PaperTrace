# INV-07 threshold policy follow-up

B accepts an input cap of at most 12,000 tokens. Its configured compaction threshold must be positive and at most `min(9000, max_input_tokens)`. A threshold of 9,001 with a 12,000-token input cap can currently postpone compaction of a 9,000-token request. The proposed fix is to apply the upper bound at B's public generation policy validation and return the existing `INVALID_BUDGET` refusal before any request capture or model attempt.

The new offline tests exercise B's product and fixed-ID evaluation entry modes. They accept thresholds of 9,000 with a 12,000-token cap and 8,500 with an 8,500-token cap. They reject 9,001 and 8,501 against those caps, respectively. Each refusal has zero captured requests, model attempts, sent IDs and citation aliases. The controls make one simulated model attempt. The existing compaction tests and plan from #76 are included with their approved contents to retain the exact-9,000 trigger, hard cap, request capture and citation coverage.

Run `python -m pytest -c papertrace.pytest.ini --import-mode=importlib -q test/offline/test_inv07_threshold_policy.py test/offline/test_inv07_answer_compaction.py` in the locked runtime. The new 9,001 cases should fail before the source change. Proposed source scope after independent test approval is B's policy validator in `src/papertrace/retrieval/service.py`, together with the previously reviewed scope of the #78 candidate. Verify the full approved set after applying the implementation on a descendant of this proposal. Product model calls in the test phase are zero.
