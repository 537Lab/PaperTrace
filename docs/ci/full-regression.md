# Gate 5: full prior regression

The executor is [`scripts/full_regression.py`](../../scripts/full_regression.py); `gates.py --gate regression --scope full` calls the same implementation. **There is no permanently BLOCKED branch**: a positive case on a complete synthetic repository passes, while negative cases with missing items, failures, skips and unauthorized live items are blocked; those are verifier tests, not evidence that the whole PaperQA2 suite passes.

## Three sources, collected in full rather than filtered by the offline marker

| Source | Interpreter and configuration | Collection scope |
|---|---|---|
| Team offline | initialized `.venv`; `papertrace.pytest.ini` | all tests under `test/offline/` |
| Team runtime/integration/live | separate runtime environment; same team configuration | `test/`, excluding only the already-run `test/offline/`, so future new directories also enter the list |
| Upstream | separate environment pinned by `uv.lock`; **original `pyproject.toml`** | `tests/` and `packages/`, keeping their doctest/typeguard settings |

Neither `-m offline` nor `-k` is passed. All unmarked tests are collected as well and executed in the default network-free environment; `live`/`live_api` items are only listed in `pending_live`, are not executed without authorization, and leave the whole gate BLOCKED. Any other deselection, collection error, empty pre-existing suite, skip, XFAIL, XPASS, or setup/call/teardown failure is not a clean regression.

Before execution, a temporary read-only snapshot is also generated from the **real Git base of the previous round**, and prior node IDs are collected with the corresponding interpreter and original configuration; the current list must contain those nodes. Thus deleting only a test function or a parametrized case, without deleting any file, cannot pass silently. Collection-only on the baseline is explicitly not a successful execution. `git archive` does not include the ignored `version.py` generated by setuptools_scm; the runner copies only these metadata from the real build of this round into the temporary base, records their paths and SHAs, and replaces no base tests or business source. A timeout keeps the collected nodes/executed results and terminates this round's process group; partial execution is not counted as complete. Missing environment dependencies are BLOCKED, code/assertion failures are FAIL; missing dependencies are never converted into initialization to let things through.

## Reproducible commands

The initialization environment is still installed per the [team entry point](../../TEAM_START_HERE.md). The team's real runtime environment is described in the [PaperQA2 verification notes](../tooling/paperqa-runtime.md). The complete upstream development dependencies are installed into another environment from the original lock (the download may be large, but it does not authorize models/APIs):

```sh
UV_PROJECT_ENVIRONMENT=.venv-upstream uv sync --frozen
uv pip install --python .venv-upstream/bin/python --no-deps --require-hashes -r requirements-upstream-test.lock
```

On the correct branch, replace `<base-40-char SHA>` with the real previous-round commit; do not copy the placeholder:

```sh
.venv/bin/python scripts/full_regression.py \
  --base <base-40-char SHA> \
  --runtime-python .venv-runtime/bin/python \
  --upstream-python .venv-upstream/bin/python \
  --output .local/full-regression
```

On Windows use the corresponding environment's `Scripts/python.exe`; absolute paths may also be passed directly to `--*-python`. By default it does not read `.env`, the personal HOME, global pytest plugins or private provider credentials; when offline it blocks Python sockets **before conftest is imported**; Unix domain sockets remain available only for local asyncio. This Python-level guard is not an OS sandbox and cannot be claimed to withstand malicious subprocesses or all external programs.

`--run-live` is for the operator to use explicitly only **after real independent test/plan approval and data/model/call-count/budget approval**; it enables networking and forwards only the environment variables of the listed providers, and may incur costs. It does not search for or read secret files. Automated CI does not pass this flag; it does not constitute an approval record, and Gate 1 and independent PR review must still be satisfied. This project has no approved real model verification, so this flag must not be run in order to get green.

## Output and acceptance

`.local/full-regression/full-regression.json` is the summary newly generated for this round; each source records the exact command, the complete collected/selected/pending_live, outcomes, stdout/stderr and a digest. It also records the SHA256 of code/test/config inputs, and a change to any input during execution fails the run. Exit codes: 0 = the complete scope PASSes this round; 1 = FAIL; 2 = BLOCKED. Every PASS covers only the interpreter, platform and versions recorded there, and does not mean the cross-Python/OS upstream matrix all passes.

The GitHub `regression` job runs **full** after installing the runtime lock and the frozen upstream environment, without `continue-on-error` and without substituting initialization. Gaps in installation/collection/actual assertions are preserved truthfully in Actions and in local records. Under the private-repository plan, a CI run still does not equal enforced merge protection; see [gate status](gates.md).
