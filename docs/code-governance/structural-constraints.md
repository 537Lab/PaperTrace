# 结构约束（D3）

依据：ADR-001（待学生批准）；INV-01–08；课程Project p5–6。应用边界只对应一处实现：A `library/` 管摄取与版本，B `retrieval/` 管上游适配/模型出站端口，C `review/` 管人工决定，D `answer/` 管上下文、生成与发布检查，E `reports/` 管历史及导出。`contracts.py` 是共用数据边界，不成为第六个全能业务模块。

薄Streamlit视图放在各自模块的view文件；装配入口只转交数据，不复制授权规则。每位成员交付一个真实功能纵切片及自己的测试、需求、设计、OpenCode监督记录和PR，不能只负责管理。只有B导入`paperqa`；D调用B公开的受控generation端口；B不得决定人工accept、D不得写C审核账本。模块交接只用共享模型，不另建同名不兼容定义。叶子模块不得循环import；入口不倒置成跨模块权威。

每个业务模块及公开函数的docstring或紧邻说明须引用所实现的REQ/INV及ADR；测试用相同ID建立可检索追踪。初始化合约中的形状约束不证明外部审核记录可信。AST检查用于捕获显式导入边界，不声称可阻止动态import或任意恶意Python。

原上游源码、解析子包、测试、锁文件默认冻结。新工作扩展基线，不复制一套PaperQA2；必要上游修复先提交新ADR，引用问题、最小diff、许可证和完整既往回归范围，经学生明确批准后单独PR。本轮没有此类业务修改。

安全路径包括契约、审核、生成/发布、版本/历史、模型配置、prompts、治理文件、CI与权限配置。变更前做影响分析、ADR及独立人工批准；规则在人审后的需求变化一个sprint内同步。不能靠改CI/测试/审批文件让自己的代码“通过”。
